Roadmap · updated October 2026

What is done, and what comes next

The specification is final. The work ahead is on Unity: the first package, com.fomoxa.unity, is out, and the next steps add physics backends and a server that runs outside the Unity player.

Timeline

Done · 2026 Specification and foundations
  • RFC-0001, RFC-0002 and RFC-0003 at v1.1.0, Final, in English and Vietnamese.
  • Version skew rules: fields appended or removed at the end of a Model (RFC-0002 §9.1).
  • fomoxac 0.2.1: codecs for Rust, Go, C#, C, C++, TypeScript and JavaScript, plus compat, ci, --watch and fomoxa-inspect.
  • Sample runtimes: fomoxa-net (Rust), Fomoxa.Net and Fomoxa.Reliability (C#), Go, C/C++ and @fomoxa/net (Node.js).
  • The implementation guide, the cross-language interop suite, and fomoxa.unity codecs for Unity types.
  • fomoxa-example-game: Unity and Go clients against a Rust server, with a benchmark.
  • This site: getting started guide, byte inspector, ecosystem and comparison pages.
Done · October 2026 Unity, stage one: com.fomoxa.unity
  • com.fomoxa.unity 0.1.0, a server-authoritative networking package for Unity 6 built on Fomoxa.Net.
  • UDP, TCP and WebSocket transports, host mode, and WebGL clients.
  • Network objects, RPCs, per-behaviour state, NetworkTransform, NetworkAnimator and network scenes.
  • Client-side prediction with reconciliation and rollback of Unity's 3D and 2D physics.
  • Codecs for Unity types generated in the Editor, in the same package.
  • Red Runner, a single-player platformer, ported to an online game as a step-by-step example.
Next Physics backends

Prediction currently rolls back Unity's built-in 3D and 2D physics. This step adds more physics backends behind the same interface, starting with Rapier, for which the package already reserves PhysicsBackend.Rapier.

Not planned

What the roadmap will not add

These are the cost of Fomoxa's guarantees, not missing features. None of them is scheduled.

  • Field tags, field numbers or names on the wire.
  • Optional, nullable or default-valued fields.
  • Varints or any other variable-width integer.
  • A mandatory IDL or schema file format.
  • Transport, framing, RPC, compression or encryption in the specification.
  • Version markers inside the byte stream.

The reasoning for each is on the home page and in RFC-0001. Suggestions and questions are welcome as issues.
