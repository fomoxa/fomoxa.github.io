Roadmap · updated September 2026

What is done, and what comes next

The specification is final. The work ahead is about the engines people build games with: Unity first, then Unreal Engine.

Timeline

Done · 2026 Specification and foundations
  • RFC-0001, RFC-0002 and RFC-0003 at v1.1.0, Final, in English and Vietnamese.
  • Version skew rules: fields appended or removed at the end of a Model (RFC-0002 §9.1).
  • fomoxac 0.2.0: codecs for Rust, Go, C#, GDScript, C, C++, TypeScript and JavaScript, plus compat, ci, --watch and fomoxa-inspect.
  • Sample runtimes: fomoxa-net (Rust), Fomoxa.Net and Fomoxa.Reliability (C#), Go, C/C++, @fomoxa/net (Node.js) and Godot.
  • The implementation guide, the cross-language interop suite, and fomoxa.unity codecs for Unity types.
  • fomoxa-example-game: Unity, Unreal, Godot and Go clients against a Rust server, with a benchmark.
  • This site: getting started guide, byte inspector, ecosystem and comparison pages.
Next 12 months · to around Q3 2027 Complete Unity libraries

Finish the set of libraries a Unity project needs to use Fomoxa end to end, building on what already runs in Unity today: Fomoxa.Net under IL2CPP, Fomoxa.Reliability, and fomoxa.unity codecs for built-in types.

In progress
The following 2 years · to around Q3 2029 Deep Unreal Engine integration

Integrate Fomoxa closely with Unreal Engine, starting from the C++ codec backend and the Unreal client already running in the example game.

Planned

Dates are estimates, not commitments. The specification does not depend on any of this work: a Unity or Unreal library is an implementation, and the wire format stays exactly as RFC-0002 defines it.

Not planned

What the roadmap will not add

These are the cost of Fomoxa's guarantees, not missing features. None of them is scheduled.

  • Field tags, field numbers or names on the wire.
  • Optional, nullable or default-valued fields.
  • Varints or any other variable-width integer.
  • A mandatory IDL or schema file format.
  • Transport, framing, RPC, compression or encryption in the specification.
  • Version markers inside the byte stream.

The reasoning for each is on the home page and in RFC-0001. Suggestions and questions are welcome as issues.
